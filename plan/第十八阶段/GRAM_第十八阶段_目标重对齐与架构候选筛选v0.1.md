## 1. 当前实际在做什么，为什么要调整

S18-2 的 PCPS 探针已经执行完成，但未通过科学门槛。之后的真实 beam 边界诊断与固定案例数值复核，用于判断旧代理指标、实际解码和评分路径是否一致。

这些工作解释了部分失败现象，却没有产生新的提点模型。最近的数值复核记录明确为 `optimizer_steps=0`、`new_checkpoints=0`、`accuracy_promotion=false`；九个案例中关闭 TF32 后评分差异缩小，不能据此推断推荐效果会提升，也不能证明先前梯度方向稳定。

证据：

- [S18-2 执行报告](../../report/第十八阶段/Stage18_S2_机制探针执行报告.md)
- [真实 beam 边界诊断报告](../../report/第十八阶段/Stage18_真实Beam边界诊断执行报告.md)
- [数值复核结果](../../artifacts/phase18/score_numerics_audit/run-0001/summary.json)

**当前决策：搁置 PCPS 作为提点主线；不自动启动之前讨论的梯度稳定性复核或 PCPS 重训。** 只有后续模型实验的解释或正确性确实依赖该问题时，才重新打开对应诊断。第十八阶段可以换候选；无需把一个失败方向的所有原因研究完，才允许推进主目标。

这是投入优先级判断，不是证明所有前缀建模都无效。当前 PCPS 主要改训练目标；S18-2 的 M0_PCPS NDCG@10 为 0.042276，低于通用损失对照 A0 的 0.043918 和打乱协同对照 S0 的 0.042834，尚无足够的机制特异性增益支持继续优先投入。若要按真实 beam 竞争重做，需要新的目标设计与训练验证，其成本不应挤占当前结构筛选。

## 2. 主问题与成功标准

研究问题：在原始 GRAM 上，能否迁移一个有来源依据的内部结构机制 M，使其独立改善推荐效果，并与冻结 PCRF 产生额外组合收益？

优先考察编码、历史交互、注意力或编码器—解码器融合的真实结构变化。单纯换辅助损失、调重排权重，暂不作为用户所需的主要模型贡献。

候选可以大幅重构 encoder、decoder、词法 / 语义 ID、输入融合与训练范式，也可以从头训练。原始 GRAM 是效果参照，不是架构不可变的边界。若改变解码预算或模型容量，记录其成本；先筛选效果，方法确定后再补匹配预算的归因实验。数据划分、目标可见性与指标定义保持可比较。

| 比较臂 | 作用 |
| --- | --- |
| A：GRAM | 复用第一、第二阶段已有基线 |
| B：GRAM + PCRF | 复用已有 PCRF 结果 |
| C：GRAM + M | 当前优先运行，寻找内部改动的独立提点信号 |
| D：GRAM + M + PCRF | 候选有希望后，使用其输出检查组合收益 |

探索阶段直接引用已有结果，按其现有数据划分、指标与评估设置比较。不能将不同 split 或不同用户子集的分数直接相减称为提点；若现有汇总与候选评估口径不同，先引用已有匹配输出或标注暂不可比，不为整理基线展开一轮新的审计与重训。已有逐用户输出可用时再作配对比较，只有汇总表时不虚构配对显著性。

当前不把四臂重跑、纯 GRAM 续训对照、多 seed 或完整消融设为候选试验的前置条件。若候选额外续训，其相对历史基线的收益先视作探索信号；方法确定后统一重跑 A / B / C / D，并根据最终训练方案补充匹配训练预算的对照，确认结构贡献。

主指标使用现有协议的 NDCG@10 和 Hit@10。Hit@50 可帮助解释候选覆盖，但不是所有内部结构都必须同时提升的唯一门槛。PCRF 按冻结算法应用于各模型自己的候选和分数，不为新模型反复调 PCRF 参数。

## 3. 旧实验不能被过度解读

`experiment/phase17/core/p1_modules.py` 开头明确说明，P1-lite 是窄机制迁移，并非来源系统的逐行复现。例如 `PawaLiteDecoderLoss` 实际是两个深度桶的损失加权，不是完整的前缀自适应解码器结构。因此，某个 lite 实验失败，不能写成对应顶会模型的完整机制已被否定。

也不能反过来把所有旧失败都归结为实现简化：LATTE-Full、SETRec-Full 等已有更完整实验，应保留各自结果。新候选必须逐项区别于已有实现，不能只换论文名字重做同一模块。

S18-2 的小样本、短续训与父模型原始训练条件不同，且纯续训对照也下降。这提示筛选协议本身需要考虑训练适配；它不足以证明 PCPS 本来有效，原失败结论仍成立。

### 候选池：商品属性与行为序列融合

- **DIFF，SIGIR 2025**：作者论文与仓库均已确认。核心是对 ID / 属性序列进行频域过滤，结合两条融合路径及表示对齐；作者实现提供 Toys、Beauty 等配置。[论文](https://arxiv.org/abs/2505.13974)、[作者代码](https://github.com/HyeYoung1218/DIFF)。
- **DIF-SR，SIGIR 2022**：可作为同一方向的较简单机制来源及对照。分别计算商品与属性的注意力，再融合注意力；作者仓库标注 Apache-2.0。[论文](https://arxiv.org/abs/2204.11046)、[作者代码](https://github.com/AIM-SE/DIF-SR)。

适配假设：在 GRAM 编码端构造有明确商品对齐关系的行为 / 属性表示，让它们在注意力计算中交互，再供原词法解码器使用。该假设来自对论文与本地架构的比较，不是已经发现的 GRAM 故障。

必须核对的差异：GRAM 已有全局历史 prompt 和逐商品文本通路，不能把动机写成“GRAM 完全没有序列建模”。DIFF 原任务是 item ID 序列推荐，迁移到 T5 / FiD 需要明确新增输入、属性可用性、隐藏状态接口与训练目标；这属于机制迁移，不能冒称完整原模型复现。DIFF 仓库首页未见标准许可证标识，本轮只确认作者公开源码；DIF-SR 的许可证已确认。

还需与本地 CF0 协同分支、HI-GRAM 层次交互以及 BiFlow 对照：只有实际保留解耦注意力或双路径过滤融合等来源机制，才构成值得独立筛选的新候选。不能退化成“均值池化后加一个门控”。

### 备选：HSTU 序列结构

**HSTU，ICML 2024**：会议论文及 Meta 作者仓库已确认，仓库为 Apache-2.0。[会议论文](https://proceedings.mlr.press/v235/zhai24a.html)、[作者代码](https://github.com/meta-recsys/generative-recommenders)。

可研究其序列计算块如何接入 GRAM 的历史表示，但官方系统及公开实验与 GRAM 的词法自回归生成存在差异，当前环境也不同。因此将其列为备选，不能依据大规模推荐结果预期本地短序列小数据一定受益；普通 Transformer 历史分支已有旧实验，需要匹配容量的对照来识别 HSTU 机制贡献。

## 5. 下一步产出与执行顺序

1. 以失败复盘为依据，对最多三条路线完成来源机制—官方代码—项目接入位置比较，再选一条实现。列出保留的核心运算、必要适配、与旧失败的实质区别、可能移除的原模型能力和训练预算。大改不会因超出旧 hook、改变 ID 或解码器而直接被排除；若迁移后核心机制不成立，则淘汰该映射。

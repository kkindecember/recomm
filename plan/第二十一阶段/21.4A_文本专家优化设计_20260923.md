## 1. 研究问题与已有证据

问题：在相同文本表示、历史和生成接口下，评价每件候选商品时单独选择相关历史，能否比当前统一兴趣向量提供更有用的文本建议，并提高完整推荐系统的净收益？

21.3B已经完成两域各512人的三组真实生成。完整组相对去文本的N10差为Toys +0.000417、Beauty +0.004845；前十命中分别净增3人、5人。真实对应也优于错配的点估计。它支持继续研究当前文本专家，但尚未证明“历史兴趣被平均掉”就是错误来源。Toys差异较小，描述性区间跨0；开发集反复使用，不作确认性结论。

21.3A显示不少文本独有正确建议在融合后没有兑现。这提醒我们区分两个问题：文本专家自己判断不准，以及文本已经判断对却没有被融合利用。本轮改的是前者；若主要改善只需改变融合，不能把它归因于新的文本匹配机制。

依据：[文本贡献结果](../../report/第二十一阶段/文本专家贡献三组并行对照_20260923.md)、[机会与兑现诊断](../../report/第二十一阶段/专家互补机会与实际兑现诊断_20260923.md)。

## 2. 原文本专家究竟怎么算

当前代码使用冻结BGE商品向量。对用户每条历史给近期权重，先把原始商品向量加权平均，最后与候选的归一化向量做余弦匹配。所有候选共享同一个用户兴趣向量。

必须保持的细节：使用原专家的`full_history`，不是擅自缩成GRAM的最近20条；衰减系数原值为0.1；历史向量先加权再归一化，不能偷偷改成先逐商品归一化再聚合。候选向量仍按原实现归一化；商品身份、文本字段和编码器缓存完全相同。

来源：`experiment/phase20/lime_comparison_core.py::semantic_users`，`third_party/LIME-Rec/lime_rec/experts.py::LLMSemanticExpert`。GRAM本来就有历史、文本和随前缀变化的注意力；本设计不能立论为GRAM不会注意相关历史。

更具体的作用假设是：外部文本专家可直接核对整个目录中候选商品的文本与历史文本是否匹配，把这份独立判断交给原有生成引导。它是否比当前专家更有用，需要完整系统对照；不能根据结构图认定互补。

## 3. 建议第一版机制

直观例子只是解释机制，不是实际成功案例：用户买过拼图、积木和遥控车。评价新的积木时，适当增加积木相关历史的权重；评价遥控车时，权重随之变化。同时保留原有近期偏好，避免非常久远的一次购买主导所有推荐。

设原始商品向量为`e_i`，归一化向量为`v_i`；历史按由旧到新排列，原权重`w_t = exp(-0.1 * (H - 1 - t))`。

- 原专家：`m_0 = sum_t(w_t * e_h[t]) / sum_t(w_t)`，`s_0(i) = cosine(e_i, m_0)`。
- 新专家：先算`a_t(i) ∝ w_t * exp(cosine(e_i, e_h[t]) / tau)`，对历史归一化后得到`m_i = sum_t(a_t(i) * e_h[t])`，最后` s(i) = cosine(e_i, m_i)`。
- 第一版设计值`tau = 0.1`，不根据开发成绩扫描温度；在实现与执行协议中先冻结再评价。这是单一配方筛查，失败不代表穷尽所有聚合方式。
- 最终仍按原作者实现逐用户归一化文本评分，然后送入相同融合器；SASRec、ItemCF的分数原样保留。
- 第一版新增可训练参数为0，不更新BGE、GRAM或商品向量；只按原配置重拟合融合器。这样可以先判断候选相关的历史重加权是否有价值，避免同时改变容量和监督。
- 新专家对全目录评分，分数在当前查询的生成开始前算好；生成过程中仍经现有接口转换为前缀分数。它不是修改alpha=0.3，也不读取当前解码隐藏状态。本轮不新增生成中动态文本注意力。

潜在代价：候选相关聚合可能过度偏向与某次购买很相似的商品，也可能忽略互补购买；计算量会高于一个兴趣向量与目录做匹配。这些都需要报告，不能预设新专家更强。

## 4. 三组主比较与一个条件性机制对照

| 组 | 文本如何处理历史 | 要回答什么 |
|---|---|---|
| A 原文本专家 | 原近期加权平均，所有候选共享一个兴趣向量 | 必须保留的旧完整组合参照；已完成结果可以核验后复用 |
| B 不看候选的历史重加权 | 用原兴趣向量`m_0`与各条历史的相似度重分配原近期权重，仍只产生一个所有候选共享的向量 | 仅更细地处理历史是否已足够；与C均为0新增参数、相同历史和向量 |
| C 按真实候选重加权 | 用正在评价的候选与各条历史的相似度计算权重 | 候选相关的历史选择是否提供额外作用 |
| D 用错候选选历史 | 用固定的另一件商品计算历史权重，但仍给原候选打分 | C若有净收益，再检验“选历史时用对候选”是否重要 |

B具体采用`a_t ∝ w_t * exp(cosine(m_0, e_h[t]) / tau)`，其余与C相同。B/C都没有额外训练参数；二者的差异是查询历史时是否使用当前候选，不是神经网络大小。

D提前确定：复用21.3B训练频次桶内的固定商品置换`donors.npy`。对候选i，用`e_donor(i)`计算权重，最后仍算`cosine(e_i, m_donor(i))`。这不同于把最终文本分数直接错配；它只破坏“用哪个候选选择历史”。记录实际改变比例及权重分布差异，不能声称除了对应关系外所有统计分布严格相同。D是输入敏感性对照，其劣化不能替代C相对A/B的净提升。

## 5. 与第20阶段旧注意力实验的区别

| 项目 | 第20阶段历史交互 | 本次设计 |
|---|---|---|
| 要改变的对象 | 固定50候选上的语义/协同双路残差排序器 | 原LIME文本专家的一路全目录评分 |
| 结构与训练 | 约16万参数注意力网络，联合多路输入，10轮训练 | 第一版0新增参数，只重拟合原融合器4轮 |
| 推荐覆盖 | 无法把50候选外商品加入列表 | 专家可对全目录提出建议；能否改变生成覆盖要实测 |
| 监督条件 | 旧训练内部前缀，原报告指出上游暴露等限制 | 当前已清理的训练末次事件留出，沿用21.3B |
| 主评价 | 原固定候选上的重排 | 原生成接口下512人真实生成；固定候选只作初筛 |

旧实验普通注意力的Toys N10相对原方法为−0.031%，不能作为已取得成功的依据，也不能重新包装为首次提出候选—历史交互。[旧报告](../../report/第二十阶段/Stage20_Toys历史交互四项对照_20260916.md)

候选相关兴趣表示已有DIN等前作：[Zhou等，Deep Interest Network，KDD 2018](https://arxiv.org/abs/1706.06978)。这次适配是待检验的具体方案，不能仅凭“加候选注意力”主张首创。它是否能成为自己的方法贡献，需要结合GRAM中的问题定位、有效配合与对照结果判断。

## 6. 在看新结果前确定的执行顺序

1. **实现前核对。** 复算A，核对历史范围、商品映射、归一化顺序和原缓存；确定性首/中/末用户与作者原评分器对齐。使用相同输入构造B/C，检查不读取目标或未来历史。允许只读训练历史来统计相似度分布和估算成本，不用开发结果调温度。
2. **先做完整目录的缓存筛查。** A/B/C均报告文本单专家、重新拟合后的融合、同一原GRAM候选上的重排表现，三层分开。不能因为文本单专家更好就宣布完整系统更好，也不能因为固定50候选未提升就断言没有生成覆盖机会。
3. **按事先规则决定真实生成投入。** 若C相对A的融合全目录N10在两域都为正且H10均不降，并且相对B至少有一域N10更好、另一域不差，进入A/B/C真实生成比较；A核验后可复用。若未满足，保留所有结果，不自动追加温度搜索或大网络。缓存门槛只管理本次计算投入，不是论文显著性或机制定论。
4. **真实生成判断。** 主要比较完整系统C−A与C−B的N10、H10、逐用户前十新增/丢失，并记录H50、目标进入/离开生成候选的情况。C−A两域N10为正且H10均不降，才支持继续投入；约1%相对N10作为优先级参考，不作为显著性标准。若C≈B，解释为历史重加权可能有用，候选相关性尚无额外支持。
5. **定位机制。** C获得上述支持后执行预先定义的D，并报告全体数据；按仅用历史文本计算的兴趣分散程度分组，切点在训练留出上固定为三分位，单条历史单列。分组只用于分析，不能按目标或收益在推理时选择专家。若多兴趣组未更受益，就不写“解决兴趣平均化”的强结论。
6. **正式确认。** 再考虑更多未用于选择的评价样本和训练种子。当前开发池反复使用；配对区间只作描述，不能充当最终test确认。单专家改动有效也不代表与后续其他专家改法组合后仍有效，仍须组合核验。

- 预定输出：分数/用户与商品映射核验、配置与源码哈希、逐组文本及融合缓存指标、逐用户真实生成结果、N10/H10/H50与新增/丢失、历史权重案例、计算与显存成本、全部失败记录。
- 本文为设计，执行入口与输出目录尚未创建，不写虚构命令或虚构运行结果。实施前另存冻结配置并确定实际资源上限。

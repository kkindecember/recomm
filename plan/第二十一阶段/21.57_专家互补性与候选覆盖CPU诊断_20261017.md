# 专家互补性与候选覆盖CPU诊断

## Material Passport

- Origin Skill: academic-research-suite / experiment-agent
- Origin Mode: validate / exploratory analysis
- Verification Status: PLANNED
- User request: “在跑的过程中 我还可以怎么探索一下 可以让双专家的效果大于单专家吗”

保持Qwen4开关GPU实验、输入与计划不变；本诊断只读已完成结果，CPU2线程，不使用正在产生的Qwen4修正预测、不读取test、不新增GPU生成或训练。分别分析原始4096/域的SASRec+BGE、SASRec+Qwen4；另分析完整开关1024/域的SASRec+惩罚和SASRec+BGE两开关。三种协议分开，不交叉比较其绝对指标。

分解双专家对SASRec的逐用户NDCG@10变化：救回未命中、丢失原命中、两者均命中时目标前移/后移。记录救回目标原本是否在SASRec前50内，用于区分排序与候选覆盖问题。标签只用于诊断结果。

保存逐用户最佳二选一路由的N10上限（oracle）并明确该上限需要目标、不能当作可部署方法或成功结果。保留SASRec前50中“在池内但未进前10”的数量，作为重排可用空间，不能视为文本能识别的证据。

两种SASRec可观测量：完整目录分数的第1−2名间隔、第10−11名间隔。阈值只来自与评估用户不重叠的既有fit用户分数，不读取fit目标。原始协议用原SASRec分数，修正协议先对完整历史商品减.05。预先固定训练分数25%、50%、75%分位点作描述分桶；只评估低25%、低50%时切换到既有双专家的四个确定性路由（2种间隔×2种门槛），其余逐位恢复SASRec预测，不挑最好门槛当确认性成果。匹配相同介入人数的固定用户哈希随机路由作控制，全部保留；配对bootstrap2000次、种子20261017、未校正多重比较。

候选覆盖采用两种池：SASRec前50与文本纯专家前50并集（最多100，只作加预算的覆盖诊断）；固定50项池（先收SASRec前25与文本前25，去重后按SASRec原顺序、再文本原顺序补至50）。固定池构造不输入目标，所有历史商品合法，没有追加目标；评估目标是否入池以及相对SASRec前50救回/丢失人数。只报告覆盖，不能把新增候选直接当作NDCG提升。BGE修正协议文本池使用去自匹配+.05惩罚的单专家分数。

保存输入文件/源码/计划哈希、用户级排名和路由掩码、固定50项候选ID、覆盖标记、分解统计、路由完整指标与区间。旧数据已是反复使用的开发用户；分桶和oracle是事后诊断，不据此宣称泛化、不将弱代理分数间隔称为校准正确率、不把跨域平均或挑选分组冒充两域稳定效果。结果用于决定后续值得验证的结构，不自动启动门控训练、候选重排训练或额外GPU实验。

# 专家辅助生成的完整逻辑与评分说明

日期：2026-10-15。承接用户要求：明确纠正哪些错误、为什么选择专家、为什么打分，以及完整方法故事。本文核对当前代码和已有全量结果，不新增训练、GPU推理或测试集评价。方法架构说明与实验支持程度分别标注；不把事后解释写成先验提出的机制。

## 1. 研究对象及实际问题

GRAM已使用顺序、历史商品文本、层级语义标识与协同邻居提示，并学习预测下一商品。研究对象不是“完全没有行为或文本信息的生成器”，而是已有多种信息的生成器在有限候选搜索下仍存在的候选选择误差。

本项目能直接观察的错误有两类：真实下一商品已经在原GRAM前50，但排名未进前10；真实下一商品没有进入原GRAM前50。三专家引导在完整validation的逐用户排名上已纠正这两类错误，同时也产生误伤。

| 旧三专家引导相对原GRAM的Top-10变化 | Toys（19412人） | Beauty（22363人） |
|---|---:|---:|
| 原11–50名进入前10 | 305 | 308 |
| 原前50之外进入前10 | 127 | 111 |
| 原前10跌出前10 | 101 | 168 |

以上重新由 `artifacts/phase21/full_validation_20260924_v1/{domain}/ranks.npz` 计算，与原summary的新增／丢失计数一致。它们是相对留出目标的排序结果，不是对每个商品真实相关性的完整判定。

同一三专家分数、同一最终路径规则下，生成引导相对后评分NDCG@10提高2.68%／1.50%；其描述性95%差值区间均为正。后评分只处理原候选，不能恢复原前50之外的目标。该结果支持生成中辅助判断的实际作用；未定位这些目标具体在哪一层前缀被原生成器淘汰，也不证明自回归概率分解本身有缺陷。

这两类结果级错误不能分别等同“缺序列”“缺协同”“缺文本”。具体专家纠正了何种属性或行为错误，需要另外的机制证据，不能用组件名称推导。

## 2. 专家组织逻辑

“序列、协同、文本”不是互斥完备的信息分类。顺序是一种行为组织方式，协同强调跨用户交互关系，文本是一种内容表示。SASRec本身同时利用顺序和所有训练用户的协同行为；不能宣称推荐信息恰好有三类，因此专家必须有三个。

对当前项目，更清楚的架构是两类候选偏好证据：

- 行为证据：用户与人群的实际交互是否支持推荐该候选。
  - SASRec：交互监督训练的有序历史预测，直接给候选分数。
  - ItemCF：直接共现统计，对当前历史支持作加权汇总，可作为行为证据的另一个实现或补充分支。
- 内容证据：候选的商品语义与历史体现的兴趣是否匹配。
  - BGE：历史文本向量近因聚合后，与候选文本向量直接匹配。

两类证据是当前研究的范围选择，也不是推荐信息的全部。三模型是候选实现，不是理论必需的三件套。双专家方案是行为预测加内容匹配的最小当前实现；ItemCF是否额外保留，应看其条件增益。更换为LightGCN等模型也必须说明其增量，模型名字不同不构成充分理由。

GRAM已经接触相关信息，但不等于在每个候选上给出与这些评分器相同的判断。尤其静态SASRec商品邻居提示没有包含当前用户的完整SASRec候选分数；历史文本编码也不是当前BGE的历史—候选显式匹配运算。这些区别支持提出互补假设，不证明每个专家不可替代。

旧全量记录中，GRAM未命中前10而至少一个专家命中的用户为1412／1440人，其中引导实际命中329／298人。此为使用目标定义的机会分析，专家机会可重叠、其余机会未必能被一个可部署门控识别。不能当作可达到的性能承诺。

## 3. GRAM也在打分

给定历史与已生成前缀，GRAM对下一词元给出条件概率。商品标识的生成分数由逐步对数概率累计得到，当前beam还使用长度惩罚。它已有用户条件下的商品选择偏好，不是只生成、不排序。

区别在于分数的入口：

- GRAM原生分数：当前前缀下，下一个词元有多合适；累计为完整商品路径分数。
- 专家原生分数：当前用户对完整候选商品的支持有多强。

用分数而不是只给一个专家推荐名单，可以保留不同候选的相对支持，并作为多种模型进入同一搜索过程的统一接口。原始分数尺度不同，需要归一化／概率化；模型分数也不自动等于校准后的可信度。

## 4. 当前实现怎样把完整商品意见接入逐步生成

实际流程：历史与候选信息 → 各专家全目录分数 → 融合商品分数 → 商品标识树上的分支概率 → 与GRAM当前词元概率混合 → beam保留下一步路径 → 最终商品列表。

一个专家认为某件商品值得推荐，就使该商品所在路径的分支获得更高支持。生成过程中使用这些支持，有机会改变哪些路径能留到最后；生成后评分只能改变已找到商品的顺序。

代码位置：`experiment/phase20/lime_decode_screen_core.py`。

当前 `ExpertTrie.conditional_logs` 先计算每件商品质量 `exp(20*(score-max_score))`，节点质量是其后代商品质量之和，下一分支概率是子节点质量除以父节点质量。

当前 `ProbabilityGuide` 保留GRAM原本合法词元概率总质量m，在合法词元条件分布上混合：`p_new(token)=m*((1-alpha)*p_GRAM(token|legal)+alpha*q_expert(token))`。之后取对数参与beam累计。alpha=0精确回到原GRAM。当前alpha固定0.3；不是把一个完整商品的GRAM总分与专家原始分数直接做7:3线性相加。

该分支分布会随前缀改变，但当前用户级专家权重并不在每个分支重新学习。不能把这种条件化称为已经实现了分支级动态专家选择。

## 5. 可以用于研究动机的完整叙述

GRAM虽然联合利用行为和内容信息，仍会把部分真实目标排低或遗漏于有限候选集合。独立的行为预测与内容匹配能够提供不同的候选判断，因此我们研究用这些商品级判断辅助生成过程。各评分器先对完整商品给出支持，再将支持转换为商品标识树上的分支概率，参与逐步候选选择。该设计既可能改善已找到商品的排序，也可能让原本未进入候选列表的商品被生成出来。已有三专家全量实验支持这两种作用，同时表明专家会产生误伤，且部分正确建议在融合与生成后仍未兑现。因此，需要研究如何以最终联合推荐收益为依据融合专家意见，而不能假定所有专家应始终同等参与。

这段叙述是问题、模块与接口的连贯解释，不是已经证明了某个新的融合器有效，也不是首次提出外部评分引导生成的声明。外部辅助生成及专家配方的相关前作和借鉴关系仍应准确保留。

## 6. 已有结论与未完成结论

已有支持：旧三专家组合在两域全量validation超过原GRAM和同规则后评分；存在已实现的排序修正与候选找回。

待验证：新双专家能否保持旧全量收益；当前两个专家各自条件贡献能否稳定成立；新融合机制是否超过调节合理的简单融合；额外计算是否值得。新双专家512人的文本Toys负增益不能隐去，也不能单独否定整个框架或旧三专家全量结果。

这次应该固定的是“商品级偏好证据辅助候选生成”这个问题与接口。专家数量、具体实现及新融合机制仍须由匹配证据决定。不能为了叙事对称强行凑出三个专家，也不能把完整故事误当成完整实验结论。

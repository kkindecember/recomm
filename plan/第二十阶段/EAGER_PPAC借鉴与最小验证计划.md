## 3. 第一项建议：个人流行度能否提供PCRF之外的信号

研究假设：同样的全局商品频次可能对应不同用户的不同兴趣证据。Jaccard邻居中的个人流行度可能补充现有CF打分；它也可能仅重复CF信息或引入稀疏噪声。实验需要区分这些解释。

### 3.1 数据和工程预检

- 复用Toys同精度原GRAM validation beam50、已冻结CF head及原PCRF，原逐用户rank必须精确对齐。
- 从prepared train重建每用户的可见训练交互；不能把训练前缀行重复计成独立用户。
- query只用推理可见的最近20条历史；邻居比较也用各用户训练历史最近20条构成集合。该序列适配与原论文完整交互集合定义的差别需记录。
- 排除query用户自己；计算Jaccard最高的30个邻居（30取自PPAC原文默认值），相同相似度按用户ID稳定排序。保留零相似度邻居时记录其数量与影响，不在看到指标后临时换过滤规则。
- PP为这30个邻居中交互过candidate的用户占比。额外记录有正相似度邻居的用户比例、候选PP全零比例、PP与原CF/全局频次的关系。
- 不读取test；query target只在最终指标汇总使用，邻居选择与分数函数不接收target。对训练前缀的后续拟合必须另行保证该前缀之后的信息不可见。
- CPU分块计算相似度，避免构造常驻的全量用户平方矩阵。小批次时间/内存已记录于统一报告及smoke.json；每域30分钟为硬上限，并非完成时间预测。

### 3.2 固定候选上的开发性对照草案

最小迁移评分为`score = score_PCRF + eta * zscore(PP)`，候选内常量PP标准化为零；原PCRF校正和权重保持不变。这只是PP信号增量试验。

建议比较：原GRAM、原PCRF、PP独排、PCRF+真实PP、PCRF+打乱用户对应的PP、PCRF+按独立用户计数的全局流行度。各臂保持同一beam50、稳定排序和同一输入预算。打乱对照的映射须在评分前固定，不能看标签挑选。

增量系数限定候选`eta ∈ {0, 0.05, 0.1, 0.2}`，用固定五折用户划分，四折选择、一折报告；三种增量特征使用相同搜索预算。此处仍是反复使用validation的开发性实验，不称新的独立确认。配置、tie-break、fold已固定，代码与输入哈希在计算指标前落盘；最新运行状态以统一报告为准。

主比较是真实PP增量对原PCRF的NDCG@10，同时报告Hit@10、头/尾变化及与打乱/全局统计对照的差异。所有臂的Hit@50应相同。既不能仅凭一个子组正向选胜者，也不能把一次小信号试验无收益写成完整PPAC无效。

如果得到值得继续的增量，再固定从Toys开发确定的配置到Beauty验证；如果未见增量，先区分邻居稀疏、与CF冗余和当前评分方式不合适，不自动扩系数网格。

## 4. 完整PPAC与EAGER的后续适配边界

**完整PPAC迁移**需要在同预算条件下训练原CF对照与PPAC适配的CF分支，区分训练变化和个人流行度的作用；不能给旧CF分数直接套原论文大系数。PPAC已经处理GP时，应单独检查与PCRF原GP校正是否重复。训练方案尚未冻结。

**EAGER适配**的实质候选是增加行为编码与行为生成分支，保留原GRAM的词法能力，先验证新分支是否提供可用于前十排序的独立信息。正式双流训练前必须核验作者实现、编码和score normalization，并记录额外参数、生成预算及共享encoder更新对父模型的影响。

已有第10阶段结果表明候选union能增加Top50却不一定改善Top10，因此不能仅凭新候选覆盖增加启动长期训练，也不能用当前CF-head union的结果代替双生成模型评估。若采用两个不同编码的decoder，其原始log概率受路径长度及训练目标影响，需要实际校准核验，不能把“confidence”名称当作概率可比性的保证。

只有各自贡献可辨认后再做组合：无新增机制、仅EAGER适配、仅PPAC适配、两者组合，并始终另列原GRAM+PCRF强参考。组合收益不能按两篇论文的提升百分比相加；即便组合提点，也要另外论证研究贡献。

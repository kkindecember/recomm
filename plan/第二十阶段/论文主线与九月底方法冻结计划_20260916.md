## 2. 首轮筛选前的问题与假设（实现已止损）

建议先筛选一个候选：**用语义兴趣相近的历史作为参照，计算协同分数相对共同兴趣背景的差值，再检验它是否有助于修正当前生成排序。** 暂不命名新算法，也不预先将这个差值解释为有效的增量信息。

具体例子：两组历史都表明用户喜欢拼装玩具，因此某件热门积木在双方协同模型中都得分很高；这部分高分可能只是在重复共同兴趣。若某款商品只对当前用户的具体交互历史得到额外高分，这个差值可能更适合用于纠正生成排序。是否如此需要实验；GRAM并非纯语义模型，不能声称共同部分一定已被它完全表达。

最小实现假设如下：

1. 冻结已有生成器、B1与独立CF模型。保留当前候选和基线分数。
2. 从合法训练历史建立参照库。使用目录文本/类别所描述的历史兴趣，结合历史长度、流行度结构匹配参照；只用预测时可见信息，不按目标、目标排名或纠错结果挑邻居。首轮固定一种已有目录表示，不另训语义编码器。
3. 对当前历史h及候选i，计算CF分数c(h,i)，并在匹配参照历史上计算背景均值m(h,i)。候选信号为e(h,i)=c(h,i)−m(h,i)。首轮只测这个差值，不同时叠加不确定性门控、多尺度邻居、候选扩展或新的蒸馏损失。
4. 在训练前缀上拟合小型有界残差修正器，以现有B1＋PCRF为起点，使用相同候选排序目标。与普通融合使用相同容量、训练样本、更新预算和选模规则；区别集中于是否使用上述背景参照。

实现可复用已有CF的归一化user/item向量：c(h,i)=s·u(h)ᵀv(i)，因此差值可由s·[u(h)−平均参照向量]ᵀv(i)计算。参照用户编码可预计算，无需每个候选反复跑Transformer。这是现有代码支持的工程可行性，不是已实测的端到端速度承诺。

这条等式也限定了方法解释：目前只是从用户向量减去参照均值，没有正交化或识别保证。即使参照用户共享语义兴趣，CF编码中的共同方向也可能含有真实且尚未被生成器利用的偏好。因此，不能从“相近用户都喜欢”直接推出“应当减掉”；当前PCRF已经校正过流行度，新差值还可能只是重复或改变这种校正。需要用第4节D臂检查语义条件是否提供额外价值。

与已做PP的区别：PP按交互重叠的Jaccard邻居统计候选热度，再正向加到PCRF；这里用语义相近历史构造CF评分背景，并研究相对背景的差值。两者确有区别，但这种区别本身还不保证创新或效果。首轮若没有增量，不能以“还没加门控”为理由无限续做。

**最可能失败的解释：** 参照匹配不准；被减掉的共同偏好实际上很有用；差值只是另一种流行度修正；普通可学习融合就能解释全部收益。因此先做简单版本，保留这些可被数据推翻的解释。

## 4. 首轮实验设计与预定去留规则（已执行）

### 第一轮：Toys，固定候选，最多三项小模型训练

| 臂 | 作用 |
|---|---|
| A：冻结B1＋PCRF seed2023 | 现有强参考，复用逐用户结果并核对对齐；不重新训练。 |
| B：普通可学习融合 | 同容量修正器，仅使用原生成/协同/流行度等已有信息。回答“多给小模型一些训练是否就够了”。 |
| C：条件参照修正 | 使用条件背景差值；其余条件与B相同。回答新信号是否有额外价值。 |
| D：简单背景参照 | 使用与C相同的差值计算与修正器，但参照只匹配历史长度和流行度结构、不匹配语义。参照库、排除规则、邻居数、训练预算和选模机会相同。回答“普通背景校正是否已经解释收益”。 |

实现时预先固定B/C/D的输入定义和实际参数量，不能给C额外训练预算或更多选模机会。沿用train-only fit/calibration边界；参照库排除当前用户，且其前缀不得携带本例的未来交互。原CF若已见过fit用户，其拟合程度属于三臂共享条件，仍需在未用于拟合修正器的用户上判断增量。

与旧B2的区别必须写清：旧B1/B2保持同一六维输入，只改损失作用于中间还是最终融合分数；本轮比较保持训练目标一致，检验条件背景信号相对原有融合信息的增量。因此不把“将最终融合纳入训练”再次作为新贡献。旧B2未显示额外优势的结论继续保留。

主评价采用完整既有Toys validation的全用户N10、H10，报告C对A/B/D的逐用户配对差值；同时记录低频表现、原有Top10正确项的损失及新命中数。不能只报covered用户、分歧用户或一个512前缀面板。固定候选意味着H50应相同，不把这一恒等性质包装成新增发现。

第一轮算力预算先以少量合法样本profile后确定：优先CPU缓存处理与小模型训练，不做fresh beam或骨干更新。限定一个工作日完成原型与首轮判断；若数据准备需要新训编码器或多天重建工程，则取消本轮优先资格。时间盒不代表保证完工，工程未完成也不判科学失败。所有具体超参数与计算上限需在查看C的验证效果前写入独立运行配置；本页不是声称配置已冻结。

### 通过后才做的跨域检查

Beauty使用Toys选定的方法结构与规则，不为两个域分别设计方法；同样保留A/B/C/D。只有Toys已经支持C具有超出普通融合和简单参照的增量，才为语义条件机制安排跨域。D已移入首轮，不等待Beauty结果后才排除最直接的替代解释。

### 去留标准

- 优先保留在完整用户上同时超过A/B，且相对D具有值得保留增量的方案，改善不集中于极少数个例。结合幅度、配对得失和区间判断，不把区间重叠解释为等效。N10为主，H10、低频和成本决定取舍；不要求八指标全部严格增加，也不只凭区间含0立即否定潜在小收益。
- 将相对强基线约1%—2%的N10增量作为投入排序的工作目标，**不是显著性阈值、录用标准或保证**。若增量更小，需要更清楚的跨域一致性或效率价值；若主指标下降而只有诊断量改善，则不能继续用诊断代替效果。
- C只胜A、不胜B：说明学习融合可能有效，条件参照尚无独立价值。保留工程结果，不据此宣称新机制成立。
- C胜A/B但相对D没有值得保留的额外收益：支持某种背景校正的工程价值，尚不支持语义条件机制；停止为该机制安排后续跨域、网格和模块叠加。正结果保存，但不能仅因总N10提升1%—2%就把它升级为论文主方法。
- 一域提升另一域下降：记录幅度和用户得失，最多一次针对明确实现/机制问题的修订，不开启按域参数网格。

这些都是长期开发validation上的选型证据。重复划分不能使其变成未消费的确认数据；冻结后另列最终确认协议，不能声称历史Toys test仍然全新。

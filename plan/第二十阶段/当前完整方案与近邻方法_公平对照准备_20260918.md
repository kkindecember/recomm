# 当前完整方案与近邻方法：公平对照准备

2026-09-18。承接用户“继续做现有完整方案与最近邻方法差异核查和公平对照准备”的授权。本轮交付源码核查、可复用数据、当前参照登记和以下实验设计；没有启动新训练。

## 1. 先回答哪个问题

当前问题不是“再加一个模块能否超过自己的最高分”，而是：**现有完整方案相对同信息、同监督的普通排序器，是否存在需要特殊设计才能保留的优势？**

按代码核查，优先补当前最强 softmax 目标下的普通小头对照，再安排完整系统近邻比较。外部方法中，LIME-Rec 与当前分数融合形态更接近；SEAR 是带评分信息的联合表示模型，应列为另一类系统对照。两者的文献关联不等于已经完成公平性能比较。

本计划不把简单对照的成功或失败当成论文录用判据，也不要求新模块额外涨 0.5%。来源与具体差异见[核查报告](../../report/第二十阶段/当前完整方案与SEAR等近邻_源码核查与对照准备_20260918.md)。

## 2. 当前完整方案的固定身份

- 方法参照：`softmax.mean`，不是旧未来软标签配方，也不是 CF coadapt 单次最高点。
- 两域小头 seed：20260917/20260918/20260919；每份部署都使用 CF2023/2024/2025 的校正分数平均。三小头指标取均值，不是把三个小头再集成。
- 参数拟合：冻结 C1/GRAM、目录头、B1、三个 CF；新增 258 参数 `Factor('next_only')` 小头，训练最终融合分数的即时目标 softmax。
- 输入：原六项特征；固定 C1 的 50 个候选；原 B1 分数作为函数起点；列表内标准化和原频次/可靠性校正保持。
- 训练前缀沿用现有 6,884/8,309 条，仍带有此前“候选覆盖且后续窗口足够”的选择限制。没有使用未来标签拟合当前 softmax，不代表已取消该样本选择。
- 两域三小头均值：Toys N10 0.087592999352、H10 0.135637749845；Beauty N10 0.074198066658、H10 0.120273070101。保留 `normalized.next_only.mean` 和旧未来配方作为辅助参照。

## 3. 第一项实验：同信息、同目标的小头必要性对照

这是在**当前最强目标**下补齐结构对照，不恢复旧 H0 原 hinge 续训、已停止的 CF 内化或门控配方。

| 臂 | 可训练部分 | 输出 | 用途 |
|---|---|---|---|
| R0 | 无 | 原 B1 标准化分数＋三 CF 校正 | 测量额外列表训练整体收益 |
| R1 | 7 参数线性残差 | `prior + 2*tanh(Linear6→1(x))` | 测量简单特征组合的能力 |
| R2 | 257 参数普通 MLP | `prior + 2*tanh(Linear32→1(tanh(Linear6→32(x))))` | 容量接近的普通非线性控制 |
| R3 | 当前 258 参数双小头 | 原 `Factor('next_only')` 实现 | 当前完整方案，读取已冻结结果并核验 |

R1/R2 的末层零初始化，初始输出必须与 R0、R3 相同。不同结构无法拥有逐参数相同初始化；匹配的是相同初始函数、随机种子、输入、目标和更新预算。257 与 258 相差 1 个参数，应如实披露，不能写成严格等参数。

所有臂最终都计算 `z(head) + r*mean[z(z(CF)-0.5*z(log1p(freq)))]`，固定原 `r`、三个 CF 和候选。训练即时目标交叉熵、头尾目标各半总权重，损失除以 50；AdamW lr0.01、wd0.01、clip10、chunk256、30 次完整 FIT 梯度累积更新，固定末步。与原 softmax 保持相同数值尺度，不能把 `/50` 删除后仍说训练一致。

新增 R1/R2 × 两域 × 三 seed，共 12 个小头、360 次正式更新；R0/R3 不重训。CPU 4 线程、总上限 30 分钟是执行上限，不是已测吞吐。运行前保存源代码/输入/配置哈希，先核对初始输出、梯度和旧 R3 全量排名；全部训练结束后一次性计算开发成绩，不根据中间验证调结构或轮数。

同时报告 NDCG/Hit@5/10/20/50、低频/非低频、FIT/非 FIT 用户、逐 seed 配对差、命中新增/损失。三份小头共享上游，不当成整条流水线独立三 seed。完整保留全部结果，不从两域中挑一域讲机制。

判断规则：R2 达到或超过 R3 时，说明本配方下普通网络足以达到该成绩，优先简化方法；R3 更高时，只记录此预算的结构差异，不能直接把双头解释成两个可识别的行为机制。微小或方向不一致的差距不安排自动网格搜索。无显著差异也不证明统计等效。

本项训练入口尚未实现/执行；可直接复用 `talos_candidate_screen.py` 的训练/评分路径，以独立文件增加两种普通小头，不能修改旧冻结脚本。执行设计参数见[配置](../../experiment/phase20/nearest_matched_head_plan_v1.json)。

## 4. 完整系统对照如何公平

| 维度 | 统一规则 |
|---|---|
| 用户、商品与切分 | 使用已核对的本地 ID 和 train/validation 记录；不因作者重新 5-core 过滤而换人换商品 |
| 主结果候选 | 每个系统面对同一合法商品目录，允许各自原生检索/生成；当前 beam50 是其系统限制。不能把 SEAR/LIME 强行限制到我们的 50 候选后称为原方法成绩 |
| 同候选诊断 | 可以另报各方法对同一 50 候选的排序，但必须标成条件诊断，并把候选外目标计为未命中 |
| 监督 | 分清训练前缀拟合、validation 拟合融合器及最终评估；不在同一批 validation 上既拟合外部融合器又和现有分数比较 |
| 元信息 | 原 SEAR 的真实评分是额外信息。保留原生评分版用于系统比较，并单列共同信息适配；常数评分或移除评分分支须改名，不能冒充原 SEAR |
| 历史长度 | 本地当前为 20，SEAR 默认 100，LIME 的 SASRec 为 50。原生长度结果与共同长度控制分别报告 |
| 已交互商品 | 明确是否过滤，并使用同一规则。当前开发集两域真实目标均不在训练历史，但历史商品仍可能占据推荐位置，过滤依然会改分数 |
| 模型选择 | SEAR 配置没有启用注释中的 NDCG@10，RecBole 1.2.0 总默认是 MRR@10；共同协议显式设置 NDCG@10，并披露与原配置差别 |
| 成本 | 测量完整生成器、目录头、CF、文本预处理、校准、排序成本；不拿新增 258 参数当整套系统成本 |
| 随机性 | 整系统复现的独立训练 seed 与本项目仅变化小头 seed 分开；不做伪等价比较 |

LIME 的原生流程使用 validation 拟合融合器，然后在 test 评价。本轮不读取 test，也不把已反复探索的 validation 重新命名为独立测试。因此当前可以做 train 内拟合的匹配适配，但必须与原生 LIME 分开。若后续采用其原生流程，应先确定所有方法共用的融合拟合/选模/最终评价数据权限，冻结方案后再进行最终评价。

SEAR 的原生复现还需要补齐真实评分及交互映射、对应文本向量和独立运行环境；源码的未来标签边界须先修正并留补丁对照。不能因为此工程问题判作者论文结果无效，也不通过删除难以提供的信息来制造一个弱对手。

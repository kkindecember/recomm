# 快速成稿定位与最小方法改造建议

日期：2026-10-10。Origin Skill：academic-research-suite，内联研究与论证审查。

状态：项目证据审查和候选方法设计完成；候选方法未实现、未训练、未评估。本文中的已有成绩属于旧组合，不能放到新方法名下。本轮新增计算仅为文档/代码索引、训练缓存覆盖计数和已有成绩差值计算，没有启动GPU任务。

## 建议先确定的方向

保留当前有效的GRAM、SASRec、ItemCF、BGE和词法树引导接口，把一次小规模改动集中到**候选证据条件下的专家融合**：原来每位用户对所有商品使用同一组三专家权重，改为根据候选与历史之间的真实支持、反向支持和缺失状态，在原权重附近作有界修正。

论文暂定题目：**Evidence-Calibrated Expert Guidance for Generative Recommendation**，中文“证据校准的专家引导生成推荐”。这是工作题目；其中“证据校准有效”仍需实验支持。

研究问题可以收窄为：**在已有多专家融合有效的前提下，候选级的历史支持结构能否帮助保留有用的专家差异，并把收益传递到生成推荐，同时减少对已有正确排序的破坏？**

这是基于现有资产的投入建议，不是保证新颖性或CCF-B录用的判断。候选级门控本身已有前作；需要验证的具体贡献是“真实评分依据的保留与有界校准，以及它在生成前使用的实际价值”。

可以以GRAM为骨干介绍整篇方法，可以给自己的完整方法起独立名称，也可以把篇幅主要放在新模块和实验上。直接借鉴的专家配方、代码与解码方式仍应在相应位置注明来源。

| 来源 | 已核实内容 | 本文怎样定位 |
|---|---|---|
| [GRAM，ACL 2025](https://aclanthology.org/2025.acl-long.1596/) | 语义到词法标识、多粒度late fusion；本项目沿用其生成骨干 | 基础模型；不能把其已有文本、序列、协同提示写成我们的新能力 |
| [LIME-Rec，2026预印本](https://arxiv.org/abs/2608.01260)及[作者实现](https://github.com/Double-wk/LIME-Rec) | SASRec、ItemCF、冻结BGE三专家，用户级分数融合和历史校准 | 直接的专家融合参照与实现来源；其原文允许重复推荐、在validation拟合，不能搬原论文数字当本项目同协议对照 |
| [AGRec，Findings ACL 2025](https://aclanthology.org/2025.findings-acl.369/) | 辅助GNN通过rankable FSM影响逐步生成，固定系数混合生成概率 | 引导解码的直接近邻；项目是受其启发的适配，未忠实复现其全部系统 |

现有源码首行直接写有`AGRec-inspired probability mixing, not an AGRec reproduction`；LIME作者门控也被直接导入。因而删去这两项引用不能构成原创性。

建议在方法里用一小段说明标准组件来源，在相关工作里解释差异；需要复制/改写的代码保留来源和许可记录。引用与以自己的方法为论文主体并不冲突。

本轮检索了三篇直接来源及“candidate-aware fusion”“item-specific gating”等近邻关键词。该检索已发现宽泛候选门控存在前作，未完成系统检索，**没有证明下面的具体组合具有排他性新颖性**。

## 4. 历史结果对新设计的约束

### 不宜再直接作为主线的小改动

| 路线 | 项目已有结果 | 当前含义 |
|---|---|---|
| 候选相关的文本历史聚合 | 21.4 C组未通过双域筛查；B组真实生成两域均未超过A | 改一个attention查询不能被当成已有正结果 |
| 按前缀动态调整专家权重 | 第20阶段四组试验未发现明确双域增量 | 同一启发式换名不构成新试验 |
| 分支延后、专家分歧抑制、路径后验融合 | 均未通过当时的双域增量条件 | 不作为快速成稿的默认押注 |
| 整体替换为专家概率算术平均 | 原512人之外，融合N10下降17.33%/11.74% | 保留部分单专家意见也可能损害原融合优势 |
| 品牌、系列、适配字符串规则 | 覆盖窄、存在错误、没有明确双域增量 | 不能把这些规则包装成完整语义推理 |
| 当前状态小头纠错 | 第2/3步信息检查未通过联合门槛，且仍是固定候选后排序 | 不能拿这个结果宣称已经训练出实时生成控制器 |
| 完整骨干替换、内部蒸馏 | 前面多阶段投入较大、稳定增量有限 | 为快速成稿不优先重开大规模结构探索 |

上述判断针对各自配方与预算，不是否定这些研究方向整体。

### 真正值得保留的项目观察

1. **专家融合有遗漏，也有额外发现。** 当前小样本的未兑现互补机会中，41/56在融合后已掉出前十；另一方面，全量概率融合对照中，原融合能找到三个专家各自前十之外的正确商品。问题不能写成“融合只会破坏专家意见”。
2. **一个用户的候选可以依赖不同的历史依据。** 同一钻饰历史，文本打分支持相似钻饰，ItemCF共现打分支持画笔；双方来源可以直接核对。共现不是功能因果，相似度也不是兼容性判定。
3. **真实依据的决策价值还没有被证明。** 21.11只动第十名时有小幅净收益，但相对分数对照的优势不稳定；训练中潜在误伤用户仅19/11位。已有特征不能直接升级为“已验证新机制”。

来源：[专家意见丢失位置](专家意见丢失位置分析_20260924.md)、[融合运算对照](分数融合与概率融合固定对照_20260925.md)、[选择性替换](专家替换建议的增量依据检查_20260925.md)、[实际依据分解](专家实际依据与语义解释对齐检查_20260926.md)。

## 5. 建议的最小方法版本

### 5.1 保留原融合为锚点

令三个归一化专家分数为`s_e(u,i)`，每项在[0,1]内；原用户权重为`w0_e(u)`，原历史惩罚为`b(u,i)`。当前分数为：

```text
S0(u,i) = sum_e w0_e(u) * s_e(u,i) - b(u,i)
```

三个专家是序列、共现和文本评分器，不改称三个新专家。第一版保留其训练、嵌入与原历史校准，便于区分新模块作用。

### 5.2 只在一个小的候选集合计算额外证据

在最近20件历史过滤后，取三个专家各自Top50和原融合Top50的并集`C(u)`，上限200件。选择候选时不使用目标。其余目录商品维持原分数，仍可以由GRAM生成；这不是把生成目录收缩为200件。

对每个`i ∈ C(u)`提取：

- 三专家评分、名次、分差，以及原融合边界信息。
- ItemCF实际打分中的历史支持数量、贡献集中程度、近期占比、无边状态。
- 文本专家实际加权评分中的历史贡献分布，而不只取最相似的一条历史。
- 相对固定参照商品的正向/反向贡献、抵消比例、支持覆盖。参照可先固定为原融合第十名；它在生成前可得，与未知目标无关。对参照自身，分差特征为0，并保留绝对支持特征。
- 历史缺失/稀疏标记。ItemCF无边表示未观察到支持，不编码为已知反对；SASRec只提供预测分数，不伪造逐历史事件解释。

第一版不加入新LLM解释、系列词典或额外人工标注。这样能直接检验现有评分来源的信息价值。

这些特征不是现实用户偏好的因果解释。“反向贡献”只表示相对于参照商品的数学分差方向。

### 5.3 候选级有界权重校准

小网络输出每个候选的三专家修正，初始化最后一层为0：

```text
w_local(u,i) = softmax(log(w0(u)) + g_theta(x(u,i)))
w(u,i)       = (1 - eta) * w0(u) + eta * w_local(u,i)
S(u,i)       = sum_e w_e(u,i) * s_e(u,i) - b(u,i),  i in C(u)
S(u,i)       = S0(u,i),                            i outside C(u)
```

`0 ≤ eta ≤ 1`控制偏离幅度。初始`g=0`时数学上恢复原融合；工程上需验证浮点数、并列排序和生成一致性。也保留`eta=0`的直接原实现分支作为精确退化检查。

在分数处于[0,1]且历史惩罚相同的条件下，有`|S-S0| ≤ eta`。因此原商品分差大于`2*eta`的二者，不会在这个商品评分器里倒序。这是简单的有界性说明，**不是最终beam排序不变或NDCG不下降的保证**；softmax和搜索仍可能放大局部变化。

保留锚点的动机来自21.10观察到的取舍：原融合确实创造了收益，直接推翻全部融合可能丢失这些收益。界限不是“安全学习”或“无损推荐”的理论承诺。

### 5.4 训练信号覆盖整个留出事件

复用与上游训练隔离的`ranker_fit`事件，冻结GRAM和三个专家，只训练新小网络。先采用标准全目录CE，可加原分布保持项：

```text
P_theta(i | u) = softmax_i(20 * S(u,i))
L = mean_u[-log P_theta(target_u | u)]
    + lambda * mean_u KL(P0(. | u) || P_theta(. | u))
```

它是普通预测与保持损失，不把CE/KL命名成新目标。对集合之外分数固定的商品，仍精确计入归一化分母和真实目标项，可以分块计算。

目标不在`C(u)`时不把它偷偷加入候选，也不删除这个用户；这类用户仍参与训练和评价。这样不会制造“训练时总能找到正确候选”的接口。

这与21.11的差异：旧版学习的是第十名替换的+1/−1/0收益，主要负例来自很少的独立用户；新版直接学习整个留出事件的商品预测。数据仍只有6083个独立训练事件，不能把所有候选或token说成独立训练用户。

### 5.5 沿用现有生成接口

修改后的商品分数按现有词法树聚合：

```text
q(v | prefix,u) = sum_{i under prefix+v} exp(20*S(u,i))
                 / sum_{i under prefix} exp(20*S(u,i))
```

继续使用现有固定`alpha=0.3`和合法token总质量保持规则。设原GRAM在当前前缀合法token上的质量为`m`，其条件分布为`p_legal`：

```text
new_token_score(v) = log m
                    + log[(1-alpha)*p_legal(v) + alpha*q(v)]
```

第一版只修改专家融合，不同时修改alpha、词法树、模型骨干或候选数量。词法树聚合和概率混合属于沿用接口，不列成新发明。准确表述是“候选证据在生成前校准专家意见，校准后的意见用于逐步生成”；不能称“生成器动态理解语言证据”或“模型每步重新选择历史”。

## 7. 一次小试应如何证明贡献

首先固定五组，使用相同上游、划分、监督和优化预算。新头参数规模与训练步数都需记录；主方法不能只与使用更少训练事件的旧门控比较。

| 组 | 内容 | 回答的问题 |
|---|---|---|
| A 原完整组合 | 当前用户级门控和固定生成引导 | 最强现成参照；退化一致性 |
| B 同数据用户级门控 | 使用与新方法相同的额外监督及预算，仍对所有候选共享权重 | 收益是否只来自更多门控训练数据 |
| C 候选分数门控 | 相同候选级结构，只用分数、名次和普通统计；匹配容量 | 收益是否只来自非线性融合和额外参数 |
| D 真实证据门控 | 完整候选级来源特征 | 拟议方法 |
| E 错配证据门控 | 保留候选和分数，按训练折及历史长度错配证据，独立训练 | 是否依赖正确的历史—候选对应 |

先在训练事件上按用户作固定交叉拟合检查数值、过拟合与D/C/E区别；之后只对固定配置作一次开发筛查。OOF和开发都属于探索，不能挑最高种子当正式成绩。

初步有价值时再做真实生成，并同时保留：

- 独立专家及完整LIME式全目录推荐，测量是否需要GRAM的在线生成成本。
- 原GRAM；旧完整组合；B/C/D关键对照的真实生成。
- D在原GRAM候选上的同规则后重排，区分新评分收益与搜索介入收益。
- D的真实/错配证据及必要专家消融；报告全部用户的N10、H10、H50、增加/丢失命中、延迟和内存。

“只看分数”的候选级门控不能省掉；只打败GRAM会把旧组合的增益错误归给新模块。错配对照也不能只在训练后的模型上换输入；独立拟合与同模型输入干预回答不同问题，应分别注明。

### 成稿决策

- **优先成稿情形：** D相对同训练预算B和候选分数C有跨域可重复的增量，真实依据优于错配；生成中使用又保留了相对同规则后重排的价值。此时可围绕一个集中贡献写论文。
- **允许总体略低旧最强组合的情形：** 同时确立了清楚的收益，例如显著降低实测服务成本、更小的训练需求或明确的稳健性优势。当前设计尚未证明任何这些替代收益。
- **应停止该版本的情形：** D与C/E没有稳定区别，或只能在少数已知案例上解释得更好；此时不能把“证据校准”当主贡献。报告试验结果，收回该机制主张。

可以暂按当前组合N10下降不超过1%作开发资源分配参考，但这是建议值，不是用户已确认的非劣界限，更不是统计等效性检验。最终仍需相对具体强对照报告差值与不确定性。

按现有资产，小头实现和缓存检查可先投入1—2个工作日；随后少量真实生成决定是否保留。完整数据集、多上游seed和最终评测的墙钟时间需测量后估计，不承诺一周即可完成全部实验。

## 8. 论文应该围绕怎样的论证展开

### 动机段草稿

生成式推荐通过逐步预测物品标识完成推荐，而序列、共现和文本匹配模型提供了互补的商品级判断。现有专家引导能够改善生成结果，但商品级融合中的信息压缩会影响后续搜索：个别专家的有效建议可能被统一权重压低，直接扩大其影响又可能破坏融合已获得的正确判断。我们研究历史评分依据能否帮助区分这些情况，并在保留原融合的基础上校准候选级专家意见，再将其用于生成解码。

这段中的“研究”是合适的当前语气。新实验通过后才能写“我们证明/实验表明该机制有效”。GRAM已有协同提示和文本能力，不写“GRAM没有协同信息或不理解历史”。

### 可检验的贡献表述

1. **现象与问题界定：** 在匹配专家和评价协议下，量化专家意见在融合与生成中的保留、遗漏和误伤，并同时记录融合独有的正确命中。
2. **待验证的方法：** 设计利用实际历史评分来源的候选级有界校准器，将单一用户权重扩展到受约束的候选权重，并通过既有词法树接口接入生成。
3. **待完成的验证：** 通过同容量分数控制、真实/错配依据、同规则后重排及训练随机性实验，区分额外训练、非线性融合、真实证据和生成位置的作用。

第1项已有开发证据，第2项只有设计，第3项尚未完成。不要在摘要里混合这三种状态。

建议正文按“问题与观察→方法→主结果→机制与成本”组织，相关工作明确连接GRAM、专家融合和外部引导解码。正文聚焦一个新模块，历史失败只选与论证直接相关的少数对照，其余保存在附录/仓库。

## 9. 快速投稿前仍必须补齐的证据

1. 当前两域全量结果是反复使用过的validation。旧项目第1/2阶段和第9阶段已经有test报告，因此整个项目不能笼统宣称“测试集从未看过”。在最终协议中列清数据使用史；冻结后评价可报告，但不凭重命名划分恢复完全未触碰的含义。
2. 当前主线只有一个上游seed。补跑门控seed只说明门控随机性；不能冒充GRAM、SASRec全链路独立重训。优先保证关键方法与强对照匹配，再安排上游重复。
3. 若资源允许，加入一个预先冻结的额外数据集。Sports在历史计划中出现过，先核对其真实使用情况，不能直接把它称为完全未见确认域。
4. 主表需要同数据、同历史过滤、同目录与同调参预算的近邻基线。LIME原论文采用不同重复推荐和拟合口径，原文分数不能直接混排。本项目的AGRec-inspired行与作者AGRec完整复现要分开标注。
5. 不能根据CCF-B这一类别保证录用。具体会议/期刊确定后再核实最新目录、征稿范围和截止日期；本轮不凭记忆承诺某个venue的等级或时间。

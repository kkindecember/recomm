## 1. 目前的判断

**候选级权重值得继续；真实历史依据暂不进入主方法。** 在相同训练事件、候选范围、小网络宽度及选轮规则下，候选分数门控在两域、三个头种子上均胜过共享用户权重。真实历史依据未稳定胜过分数版，且两域均未超过错配历史对照，不能写作已证实的机制。

这比仅声称“整个组合优于GRAM”多了一项实证增量，但还不足以保证CCF-B录用。候选门控属于已有研究范式；本项目需要靠明确的问题、具体实现差异、强对照和生成中的实际收益构成贡献，而不是宣称首次发明候选门控。

## 2. 做了什么

- 冻结原GRAM、三个专家、原门控及历史惩罚。训练数据仅为专门留出的训练末次事件：Toys 2773、Beauty 3310名独立用户。
- 用户哈希划分内部20%留出，按CE+0.2KL选择0/4/8/12/20轮之一，再用全部训练留出重拟合；外部validation不用于拟合或选轮。
- 每域5种新头×3个种子，共30个最终模型。最多200个候选来自三专家及原融合各Top50并集，排除最近20件历史；集合外分数原样保留。目标不在集合也继续参与完整目录损失和评价。
- 全部41775个validation事件完成评价；主分析排除所有门控拟合用户及旧512人，保留Toys 15406、Beauty 17766人。全体用户结果另报，不按目标是否在候选内筛选主结果。
- 同一72维输入接口、32隐单元、3输出，共2435个参数；不使用的输入置零。实际活跃输入B/G为18维、C为36维、D/E为72维，不能据此宣称信息容量完全相同。
- eta=0.1有界修正，输出层零初始化。损失为完整目录CE(20*S)+0.2KL；候选外质量精确进入分母。AdamW lr0.002、weight decay0.001、batch64。
- 文本使用原始BGE向量、原衰减池化及归一化的真实逐历史贡献；CF使用真实共现邻居和原位置权重。统计支持集中度、正负贡献、近期占比及相对原融合第十名的抵消，不加入语言解释或品牌规则。SASRec没有伪造逐历史归因。

| 标记 | 方法 | 用途 |
|---|---|---|
| A original | 冻结原融合 | 现有组合的商品评分基线 |
| B user | 同数据训练，C内共享一组用户权重，C外不变 | 控制额外训练数据与修改范围 |
| C score | 候选分数、名次、分差等决定局部权重 | 检验候选条件化 |
| D evidence | C加真实历史贡献结构 | 检验历史依据增量 |
| E shuffled | C加相近历史长度、同划分其他用户的历史结构，独立训练 | 检验真实对应关系是否必要 |
| G global | 同数据用户权重作用于完整目录 | 检查B只修改局部范围的局限 |

“分数版”包含候选名次、分差、训练频次与用户统计，不是只输入三个浮点数。D/E相同结构，所有供体均与原用户不同；供体选择不使用目标。用户统计在两划分均用同一CPU实现，原GPU topk并列处理与CPU最大差0.2只出现在原统计对照记录中；原权重始终直接复用缓存。

## 3. 两个假设的实际结果

以下为主分析用户的全目录商品排序NDCG@10，三个头种子均值±样本标准差。它们共享一个上游模型，标准差不是骨干训练方差。

| 方法 | Toys | Beauty |
|---|---:|---:|
| A 原融合 | 0.081115 | 0.071652 |
| B 同数据用户门控 | 0.082328 ± 0.000071 | 0.073428 ± 0.000037 |
| C 候选分数门控 | 0.084480 ± 0.000354 | 0.075421 ± 0.000123 |
| D 真实历史依据 | 0.085043 ± 0.000251 | 0.075033 ± 0.000321 |
| E 错配历史依据 | 0.085140 ± 0.000164 | 0.075166 ± 0.000177 |
| G 完整目录用户门控 | 0.082225 ± 0.000092 | 0.073251 ± 0.000075 |

### H1：同一用户对不同候选使用不同权重

| 比较 | Toys | Beauty |
|---|---:|---:|
| C−B绝对N10 | +0.002152 | +0.001994 |
| 用户配对95%描述性区间 | [+0.001212,+0.003107] | [+0.001029,+0.002919] |
| 相对B | +2.61% | +2.71% |
| 相对A | +4.15% | +5.26% |
| C−B三个种子方向 | 全部为正 | 全部为正 |

C也超过作用于完整目录的G。全体19412/22363用户中，C相对B分别+2.58%/+2.60%，方向一致。因此本轮支持继续研究**这个候选级配方**；不能把结论扩展为所有候选门控必然更好，也不能把这张排序表直接移到生成推荐主表。

命中变化并非没有代价。固定seed0的primary中，C对A在Toys新增182例、丢失104例，Beauty新增290例、丢失154例；C对同数据B分别新增144/220例、丢失98/136例。C对A新增中还有76/114例不属于任何单专家原前十，说明改动仍包含融合后的额外发现，不能只描述为恢复被压制的单专家意见。全部种子的[新增/丢失计数](../../artifacts/phase21/candidate_gate_20261010_v1/gain_loss.json)已保存；这些目标条件分组是描述分析，不是因果归因。

### H2：真实历史依据比只看分数更好

| 比较 | Toys ΔN10及95%区间 | Beauty ΔN10及95%区间 |
|---|---|---|
| D−C | +0.000563，[-0.000104,+0.001173] | -0.000388，[-0.001061,+0.000262] |
| D−E | -0.000097，[-0.000834,+0.000613] | -0.000132，[-0.000828,+0.000562] |

**未通过。** Toys三个种子D均略高于C，Beauty三个种子均低于C；D对错配历史也没有稳定优势。因此不将当前方法命名为“历史证据驱动”并把这个机制写成已经成立。该结果限制当前特征与训练配方，不证明所有真实历史信息都没有价值。

此外，这些依据含原始贡献总量，若未来出现强正结果，还应加入“只保留原始总分、去掉分布结构”的对照，排除仅由分数尺度信息造成的提升。本轮H2未过，无需为此先扩大训练。

## 4. 已经能针对GRAM指出的具体问题

这里重新核算的是9月24日的旧完整生成输出，不是新门控的成绩。逐用户从候选和分数重排，全部复现旧排名；旧late与GRAM候选集合逐行相同。

| 旧组合的生成诊断 | Toys | Beauty |
|---|---:|---:|
| 原GRAM N10 | 0.072201 | 0.071888 |
| 同信号后重排N10 | 0.080322 | 0.077545 |
| 旧生成中引导N10 | 0.082475 | 0.078705 |
| 引导相对后重排新增前十命中 | 127 | 111 |
| 其中目标原来在GRAM候选50之外 | 127 | 111 |
| 引导相对后重排损失前十命中 | 33 | 47 |
| 新进入生成候选50的正确目标 | 748 | 755 |
| 原在候选50中但被引导丢掉的目标 | 166 | 272 |

同信号后重排已经解释整个组合相对GRAM的大部分N10增益。生成中引导相对后重排的额外N10，可精确拆为：

| guided−late对整体N10的贡献 | Toys | Beauty |
|---|---:|---:|
| 原GRAM候选内的目标 | -0.000742 | -0.000897 |
| 原GRAM候选外的目标 | +0.002895 | +0.002056 |
| 合计 | +0.002153 | +0.001160 |

因此，**目前最有证据的动机是候选可达性与排序的分离**：后重排可以排准已有候选，但不能补回候选集之外的商品；外部商品评分提前影响搜索能找回其中一部分，同时存在误伤。排除拟合用户的primary上同样成立。

不能由此声称已经定位了具体剪枝层，或证明token概率偏差是唯一原因。若要写“第几步早剪枝”，仍须逐步轨迹和对应干预。也不能说GRAM没有协同或文本能力：[GRAM原文](https://aclanthology.org/2025.acl-long.1596/)明确包含协同关系编码及多粒度语义融合。

融合层另有可量化的损失：在“GRAM未进前十、至少一位专家进前十”的机会中，旧引导仍未兑现1083/1142例，其中685/762例的目标在原融合后就已不在前十。这是观察到的排名位置，不能当作新方法能全部救回的上限收益。

可用于论文的问题表述：

> 在固定生成预算下，生成器的候选集合可能遗漏外部评分器能够识别的相关商品，因此仅在生成后使用专家分数会限制其作用。同时，不同候选的专家分歧结构并不相同，用同一组用户级权重处理所有候选可能限制融合表达。我们研究以原融合为起点的候选条件化校正，并检验其收益能否通过商品到前缀的概率映射传递至真实生成。

其中候选遗漏已有生成证据，候选条件化已有本轮排序证据，“传递至真实生成”正在验证。该段不是对所有生成推荐器的普遍失效宣言。

## 5. 创新风险与必须补齐的证据

已有标准组件组合可以形成自己的系统，但当前能主张的新贡献应具体到C的实现与经验证的作用。候选门控、专家融合、图辅助解码均存在前作；[AGRec](https://aclanthology.org/2025.findings-acl.369/)已使用辅助图模型调整自回归解码并处理搜索范围问题。不能把“首次用专家辅助生成”当作本项目的广泛首创主张。

| 优先级 | 尚缺什么 | 为什么值得先做 | 本轮进展 |
|---|---|---|---|
| P0 | 新C真实生成 vs 旧组合A、同数据B、自己的late | 防止排序代理指标提升却损害生成 | 21.19B已启动，每域2048、固定seed0 |
| P0 | 新C专家融合单独排序 vs C引导生成 | 检查生成器在新评分器之上是否仍有价值 | 已有全目录排名，可直接在相同用户集合统计，无须新训练 |
| P0 | 相同输入的标量残差排序器 | 排除任何普通候选小排序器都能解释收益 | 21.19C正在执行 |
| P0 | eta1与eta0.1的固定对照 | 区分理论变化上界与实际锚点价值 | 21.19C正在执行 |
| P1 | SASRec、ItemCF、文本的同预算删除对照 | 证明各专家是否必要，决定能否简化方法 | 现有SASRec/ItemCF运行有失败记录，不能算已完成；文本只有小样本完整对照 |
| P1 | 新方法完整生成评价、配对新增/丢失 | 小样本迁移正结果不足以形成最终主表 | 通过迁移筛查后执行 |
| P1 | 至少补骨干训练随机性 | 本轮三个种子只覆盖小头 | 现有一次骨干训练Toys约22.5h、Beauty约31.8h，需提前排程 |
| P1 | 同信息、同协议的直接近邻与强简单对照 | 排除更多数据、更多候选或更多训练造成的解释 | 本轮已补同数据用户门控及完整目录控制；旧分数不能跨协议搬表 |
| P1 | 耗时、显存、专家预计算和训练成本 | 外部专家及缓存成本不能省略 | 本轮仅有分项运行时间；尚无完整端到端效率结论 |
| P2 | 同预算宽beam/大候选后排参照 | 检查是否只需扩大搜索预算 | 第11阶段已有旧512人beam50/100/200结果，不能当作当前干净模型的匹配对照 |
| P2 | 第三个数据集 | 增强外推范围 | 前述核心对照稳定后再启动 |

目前不需要证明每个模块都从零原创，也不需要把主表所有提升归给新小头；需要明确区分“已有组合的增益”和“C在强已有组合之上的增量”。直接使用或改写的实现应保留来源说明；写作重点可以放在自己的问题、设计和实验证据。

## 6. 一周执行顺序

| 时间 | 产出 | 决策条件 |
|---|---|---|
| 第1天 | 完成H1/H2、结构控制及真实生成迁移筛查 | H2当前不保留为核心贡献；根据C真实生成及简单控制决定主方法 |
| 第2天 | 固定方法与对照；开始完整生成；具备正信号后尽早启动额外骨干种子 | 不按某个最好小头种子替换固定主配置 |
| 第3–4天 | 补缺失专家消融、强简单对照、误伤与新增分析 | 删除无必要的专家或模块也可成为简化结果，完整保留负结果 |
| 第4–5天 | 收齐骨干重复、运行成本、正式评价口径 | 训练时间是既有运行实测参考，资源竞争会改变完成时间 |
| 第6–7天 | 写定方法、结果、消融、局限；补相关工作和投稿格式 | 第三个数据集仅在核心结果已完成且资源允许时追加 |

最终评价前须明确数据使用历史：当前validation已反复开发，部分旧阶段也消费过test。不能把重新分折或更名后的数据说成未见确认集。方法固定后应尽可能安排未消费的确认数据；若只能复用既有benchmark，完整披露开发过程与局限。

这个顺序优先完成会直接改变选型或回答审稿质疑的证据，不给未经估计的“成功概率”百分比，也不保证增加模块能提高录用率。

## 7. 数值核验与统计边界

21.19主运行928.72秒，CPU最多4线程，未使用GPU。零修正、eta0、完整目录压缩损失及梯度与密集计算均通过；真实历史贡献与既有逐事件实现对齐。原分数在抽查中重构误差为0。

独立NumPy网络前向及完整排序核查301条模型×用户记录，301条排名完全一致；384项全用户汇总指标检查通过。29份输入/代码哈希核验，12项与原来源清单直接匹配；原融合排名与既有独立审计全量一致。这里的“独立”指不同数值实现，同机复核不等于独立研究团队复现。

统计处理：按域报告，防止合并掩盖方向差异；实验单位是用户，候选与头种子不能膨胀样本量；全部用户而非只选命中机会用于主结论；报告全部种子、失败分支及对照，不挑最好结果；候选覆盖分组只作描述，不作因果结论；历史只来自允许的观测事件，特征函数不接收目标。结果是多轮探索后的描述性比较，bootstrap区间条件于固定模型，未做整个项目历史搜索的多重校正。

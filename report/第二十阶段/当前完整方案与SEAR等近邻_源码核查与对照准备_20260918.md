# 当前完整方案与 SEAR 等近邻：源码核查与对照准备

2026-09-18。使用 academic-research-suite，单会话完成项目代码审读、作者材料核对、合成数据检查及本地 train/validation 数据准备。**没有训练新推荐模型，没有得到 SEAR 或 LIME-Rec 的本地准确率，也没有读取 test。**

结论：当前 NDCG 效果参照应准确描述为“固定生成候选上的即时列表训练＋协同校正”，而不是未来软标签模型。SEAR 与其监督、输入和预测空间均不同；LIME-Rec 在分数融合形态上更近。下一项应先补当前最强训练目标下的普通小头控制，同时保留完整系统近邻比较，不能通过删掉对手的输入或换评估范围得到一个看似公平的成绩。

## 1. 当前模型实际是什么

核对 [talos_candidate_screen.py](../../experiment/phase20/talos_candidate_screen.py)、[Factor 实现](../../experiment/phase20/future_factor_screen.py)、[六项特征](../../experiment/phase20/gacr_features.py)及冻结结果后，实际流程为：

1. 冻结 C1/GRAM 生成 50 个候选；候选不因后面的新小头而扩张。
2. 用目录头分数/名次、生成名次、两种来源指示和历史—商品余弦共六项特征，得到已有 B1 残差分数。
3. 在 B1 起点上训练 `Factor('next_only')`，内部保留两个 `6→16→1` 小头，共 258 参数；当前只用即时下一件目标，通过最终融合分数计算普通 softmax CE。
4. 对小头输出做列表内标准化，加入三个冻结 CF 的校正分数平均。CF 校正包含固定的频次扣分与原 B1 低频比例形成的可靠性系数。

两小头是之前因子化探索留下的计算结构；本版没有分别监督“近期会买”和“下一件先买”两个语义。**不能仅因代码里有两个分支，就声称已学到两个可解释机制。** 原始生成器、目录头和三个 CF 的训练/推理开销也不能从方法描述中消失。

训练使用此前筛出的 Toys 6,884 / Beauty 8,309 条前缀，30 次全 FIT 更新，固定末步。当前标签不含未来商品，但样本集合仍沿用先前有完整未来窗口的选择。三份结果只改变小头初始化；`mean` 指三个 CF 的分量平均，不代表三份小头再集成。

| 当前完整方法 | 三小头均值 NDCG@10 | 三小头均值 Hit@10 |
|---|---:|---:|
| Toys softmax.mean | 0.087592999352 | 0.135637749845 |
| Beauty softmax.mean | 0.074198066658 | 0.120273070101 |

本轮从六份已保存排名重算上述指标，并逐用户、逐商品校对目标在候选中的位置；checkpoint 路径及哈希纳入清单。未重新前向模型或重训，不把这次检查称为独立性能复现。[结果与来源清单](../../artifacts/phase20/nearest_comparison_20260918/summary.json)

## 2. 与近邻工作的实质差别

| 对象 | 方法与监督 | 与当前方案的比较意义 |
|---|---|---|
| 当前完整方案 | 冻结生成候选、六维排序特征、即时列表目标、独立 CF 分数校正 | 当前效果参照；额外小头结构必要性仍需直接控制 |
| SEAR | 语义/协同/评分三种表示经交互聚合和 Mamba 序列层，输出全目录分数；用后续交互及评分构造软分布 | 适合作为完整多信息系统对照；不属于“同候选上换个融合头” |
| LIME-Rec | SASRec、ItemCF 与冻结文本向量分别评分，再做轻量融合与历史校正；融合器在 validation 拟合 | 在分数融合形态上更近，但监督划分必须对齐；本轮仅核对正文、附录和作者仓库说明 |
| PRORec / UNGER | arXiv 2502.06269 的 v1 名为 PRORec，v2 已改名 UNGER；统一码本及生成模型内的知识整合 | 属于内部表示/生成路线的相关工作；与固定 beam 后排序不是同一个模块，当前不直接移植其完整框架 |

SEAR 身份与总体设计由 [WWW2026 官方论文目录](https://www.sigweb.hosting.acm.org/toc/www26a.html)和[作者仓库](https://github.com/guanwei49/SEAR/tree/4dc184400d96a93d74d14270f5f8c869b667a835)核对；实现细节以下述固定代码为准。LIME-Rec 的来源为[预印本正文与附录 E](https://arxiv.org/html/2608.01260v1)及[官方仓库说明](https://github.com/Double-wk/LIME-Rec)，不将预印本说成已录用论文。PRORec/UNGER 的版本区别以 [v1](https://arxiv.org/abs/2502.06269v1)、[v2](https://arxiv.org/html/2502.06269v2)为准。

这些差异解释了为何要比较，**不自动构成我们的创新**。本轮没有穷尽所有近邻研究；SEAR 的正式全文未能通过本次 DOI 页面获取，因此没有核实其全部实验表和消融，不填造论文成绩。

## 3. SEAR 作者代码的具体核查

原仓库已下载至 [third_party/SEAR](../../third_party/SEAR/)，固定 commit `4dc184400d96a93d74d14270f5f8c869b667a835`，作者提交时间 2026-08-27；未修改源码或运行作者主训练入口。网页缓存中曾返回更早的损失接口，本次以固定 commit 的源码为准。

### 3.1 评分是实际输入和监督，不是可随意补的字段

[model/sear.py](../../third_party/SEAR/model/sear.py)从历史评分构造第三路表示；文本来自 `all-mpnet-base-v2`，PCA 结果还用于协同 embedding 与目录输出层的初始化。模型直接输出全目录 logits。

[model/loss.py](../../third_party/SEAR/model/loss.py)对第 j 个未来交互赋予 `rating_j * exp(-2j)` 权重，归一化后以 KL 训练。对重复商品累积概率。合成样例验证源码与独立计算的公式一致，也验证用常数评分会改变损失。因此不能声称本地普通倒数位置软标签就是 SEAR 的忠实复现。

默认配置为 k=4、history100、hidden64、两层、batch2048、最多200轮及指数学习率衰减。作者模型配置的 `valid_metric: NDCG@10` 被注释；所列 RecBole 1.2.0 的[总体默认配置](https://github.com/RUCAIBox/RecBole/blob/v1.2.0/recbole/properties/overall.yaml)采用 MRR@10，[序列任务配置](https://github.com/RUCAIBox/RecBole/blob/v1.2.0/recbole/properties/quick_start_config/sequential.yaml)采用时间顺序留出。后续应打印实际合并配置，不能凭注释认定按 NDCG 选模。本轮未安装该环境，所以这一项是源码默认值核对，不是实例化运行验证。

README 给出的 `custom_trainer.py` 是 Trainer 类文件；实际带 `main` 的运行入口是 [run_custrainer.py](../../third_party/SEAR/run_custrainer.py)，其中会进入 test 评价，本轮未执行。

### 3.2 未来标签的长历史边界问题已合成复现

[seq_dataset.py](../../third_party/SEAR/seq_dataset.py)把会随历史窗口移动的 `seq_start`，也用于计算未来标签应停止的用户边界。当序列超过窗口时，截止点可能被向后推移。

在两个合成用户、长度 106 和 8、history100、k=4 的例子中，第一用户最后一个训练目标位于下标 103；合法后缀只有该训练目标。作者索引代码会取下标 103、104、105、106，其中 104/105 是合成留出位置，106 已属于下一用户。history20 的对应例子也复现。

检查执行的是原 `data_augmentation` 中的索引构造语句，通过 AST 提取，在合成 ID 上运行；没有读取本地 test。修复原则是将固定用户起止边界与滑动历史起点分开，或像本轮导出器一样只在独立的 train 序列内取后缀。

这是**固定源码的边界缺陷**，不是作者论文的泄漏影响量测。未获取其实际运行配置/产物，不能推断论文成绩因此提高多少。我们数据中训练序列超过100的用户分别有16/17人，也不能把这个人数直接当成作者实验受影响人数。

另检查全 padding 标签的零分母：当前 PyTorch1.11 的 KL 返回0，而非最初预想的 NaN；未声称该情形出现在合法训练样本中。数据导出保证每行至少有当前目标，防止空软分布。[源码审计结果](../../artifacts/phase20/nearest_comparison_20260918/sear_source_audit.json)

在不读取原始含 test 的用户序列文件的情况下，从已有 train 前缀逐用户重建完整训练序列，检查每一步 history 与原记录一致；验证历史也与该序列末20件逐条相同。导出了 20/100 长度的右侧补零历史、训练位置、即时目标、train 内四步后缀及逐商品元信息。短后缀补0，不跨用户，不借 validation 延长未来标签。

元信息已有 title/categories/description/price 等字段；Toys 的 brand 全部缺失，Beauty 也非全覆盖。评分与时间戳在本轮核对的标准记录和已搜资产中未找到，不能凭相同用户/商品数量认定与作者输入逐条相同。商品文本和协同信息的预处理范围仍需与未来对照保持一致。

当前 `gram-repro` 是 PyTorch1.11/CUDA11.3，缺 RecBole、Mamba、causal-conv1d、sentence-transformers，已检查缓存中未找到 MPNet 对应资产。SEAR README 给出另一套环境；没有直接升级当前可复现实验环境。现有有序序列足以提供排序索引，时间戳缺失可以通过显式数据适配处理，不能因此说序列模型无法使用；真实评分仍是忠实保留评分分支所缺的信息。**原生 SEAR 尚不具备开训条件，当前完成的是对照数据和核查准备。**

全体输入及产物哈希、六份小头路径和指标登记在 [manifest](../../artifacts/phase20/nearest_comparison_20260918/manifest.json)及[summary](../../artifacts/phase20/nearest_comparison_20260918/summary.json)。准备脚本为 [prepare_nearest_comparison.py](../../experiment/phase20/prepare_nearest_comparison.py)。

## 5. 下一项的明确选择

先比较当前 258 参数双小头与容量接近的普通 257 参数 MLP，并加7参数线性控制。保持当前最强 softmax 目标、相同训练前缀、初始输出、三 CF、候选、校正和更新预算，直接回答“当前结构是否比普通排序器有必要”。这项局部控制不能替代外部系统基线，也不被命名为新模块。

完整系统对照应分别记录：当前系统与 LIME/SEAR 的原生检索能力，以及同候选上的排序诊断。SEAR 真实评分、LIME 的 validation 拟合监督、各自历史长度与选模指标都要明示，不能混在一个表里暗示完全同条件。具体实验臂、360次更新预算和公平规则已写入[可执行设计](../../plan/第二十阶段/当前完整方案与近邻方法_公平对照准备_20260918.md)。本轮没有实现/运行新小头训练入口。

目前能保留的论文候选是完整流程的受控有效性；“未来标签独有贡献”“两个小头分别学到两类偏好”“低参数等于低总成本”均没有因此成立。若普通网络足以恢复当前效果，就简化方案并重估贡献；若存在差距，再检查稳定性与具体作用，不能直接给差距换一个机制名字。

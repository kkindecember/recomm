# LIME 前缀专家权重四组筛查（冻结协议）

Origin Skill：academic-research-suite / experiment-agent，内联执行，无子代理。
用户授权：在删除历史校准的讨论后，提出动态专家权重和四组对照，用户回复“那做吧”。

## 假设与边界

已有 SASRec / ItemCF / BGE 三专家在不同词元前缀对应的商品子集中，可能有不同的区分能力。
只检验轻量的前缀权重调节是否优于固定用户权重；不训练新模型，不引入第四个专家。
局部分数差异不是准确率证据，尖锐的错误专家也可能被放大，因此必须同强度比较。
本轮不主张新颖性，不将设计本身等同于可发表贡献。

## 固定规则

每个前缀 p、专家 e：

1. 对其后代商品用已有的逐用户 min-max 专家分数，scale=20 的 softmax 聚合到下一合法词元，得到 q_e。
2. 以各子分支的后代商品数量占比 q_size 为结构参照。计算 g_e=JS(q_e,q_size)/ln(2)，范围 [0,1]。
3. w_e(p)=w_e(user)*(1+g_e)/sum_f[w_f(user)*(1+g_f)]。乘性调整因子固定在 [1,2]，不增加可选参数。
4. 使用原来的“商品分数加权求和→历史惩罚（开/关）→scale=20→聚合到词元”公式。
5. 与原 GRAM 合法词元概率混合，保留原合法概率总质量，alpha=0.3。

权重仅依赖训练期历史和冻结的专家分数，不接收评价目标。历史惩罚不参与局部权重计算，所以开关校准的两组使用完全相同的局部权重。
只有一个合法子分支时，条件概率直接为1。动态权重改变的是三个专家之间的相对权重，不是仅改变外部专家与 GRAM 的混合强度。

## 四组与对照

| 组名 | 专家权重 | 历史校准 |
|---|---|---|
| fixed_cal | 已有用户固定权重 | 开 |
| fixed_no_cal | 已有用户固定权重 | 关 |
| dynamic_cal | 前缀动态权重 | 开 |
| dynamic_no_cal | 前缀动态权重 | 关 |

四组统一 alpha=0.3，沿用已完成原实验两个域各128人选出的 LIME 强度，不重新选参。
额外保留原 GRAM、独立 LIME、直接 LIME 分数重排 GRAM50、四组各自的同规则后重排。
动态权重仅从当前前缀计算，因此完整候选也能按完全相同规则在原 GRAM50 上复算。
固定校准组直接用已核对的原始 LIME 分数，避免重新融合产生基线误差。

## 用户、资源与计时

Toys、Beauty 各3名原工程用户做零强度退化、合法路径、分数重构和共享商品后重排一致性检查。

评价各512人，排除原第一轮643人、第二轮机制筛查643人、门控2048名拟合用户。
剩余旧 LIME 评价缓存用户按 SHA256('20260921|lime-prefix-expert-v1|domain|user') 排序，取前512人。
不读取第二轮评价结果选择本轮方案。仍然是反复使用过的历史开发集，不能声称独立最终测试。

Toys 使用 GPU 1，Beauty 使用 GPU 6，以 UUID 固定。与现有任务共享资源，显存空闲>=12GiB时启动，每进程上限11GiB，CPU数学线程2。
beam50，原词元路径和模型不变；每域18次工程解码+512*5次评价解码=2578次。
不设强制墙钟中止，不自动重试或追加实验。宿主机 tmux 后台运行。
每用户轮换四组执行顺序，缓存收益和共享GPU竞争使各组耗时仅为粗略诊断，不视作正式公平效率基准。

## 结果与继续门槛

主指标 NDCG@10，同时保留 N/H@5/10/20/50、逐用户结果及成对差值和固定种子2000次bootstrap描述性区间。
动态组分别与同校准条件的固定组比较；不只比较原 GRAM。所有四组结果完整保留。
动态方案双域相对相应固定组 N10>=+0.5%、H10净增>=0，且相对 GRAM N10>=+1%、H10净增>=0，才标为值得干净流水线复验的候选。
删减校准单独判定：双域相对对应校准组 N10>=-0.5%、H10/H50净损失不超过1名用户，标为简化复验候选；这是资源分配容忍度，不是统计等效性证明，也不是已证明加速。
若无双域一致增益，不自动扩大参数网格。本轮旧模型上的结果不代替后续干净基线、多种子和最终测试。

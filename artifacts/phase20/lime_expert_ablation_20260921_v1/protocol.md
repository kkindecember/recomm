# LIME专家删减：CPU并行诊断

Origin Skill：academic-research-suite / experiment-agent，内联执行。2026-09-21用户询问是否值得并行增加探索，授权筛选有价值方向；本轮限定为复用缓存的CPU诊断。

## 研究问题与成本

正在运行的机制实验检验介入位置和强度。本轮单独检验信号组成：冻结LIME门控后，删掉某专家是否保留或改善信号质量，从而值得在下一轮解码中简化或重新设计专家融合？只用CPU两线程，不新增模型训练或生成，不修改正在运行的实验，不读取其选参/评价结果，不自动启动GPU跟进。

使用刚完成的完整生成筛查的原512评价用户/域。该集合已经看过，只作事后开发探索；不要误称新的独立验证。两个域所有用户都保留，不按目标、命中、候选覆盖挑人。原数据和代码保持不变，所有新增文件单独保存。

## 固定变体

原专家顺序为SASRec、ItemCF、BGE。归一化保留作者逐用户min-max定义。保留原门控权重和历史校准强度，不训练新权重、不扫温度或混合比例。

1. 完整LIME。
2. 去ItemCF：SASRec与文本保留原权重比例，除以两者权重和。
3. 去文本：SASRec与ItemCF同样重归一。
4. 去SASRec：ItemCF与文本同样重归一。
5. 去历史校准：完整原加权信号，不减历史惩罚。
6. 等权控制：三专家各1/3，保留原历史校准。
7. SASRec单独：原归一化SASRec分数，不加历史校准，与现有单专家引导信号一致。

删减同时改变了剩余信号强度相对固定历史惩罚的比例，因此是具体冻结配方的干预，不能唯一归因于某信息来源，也不能证明重新拟合后的最优删减系统如何。

## 三个评分口径

- 全目录Top50：观察信号自身的检索/排序质量。
- 固定原GRAM50：观察它在相同原生成候选上的排序质量。
- 固定旧LIME引导50：辅助诊断新增候选竞争；由于候选来自完整LIME引导，不能视为独立、公平的替代信号生成测试。

共同过滤最近20件历史，不补满原50候选；同分按商品数值ID。历史校准针对完整训练历史，与最近20件硬过滤不同。复现完整LIME的全目录和GRAM50 Top50/名次必须与旧缓存逐项一致，否则先报工程错误，不解释变体成绩。

主要指标NDCG@10；报告Hit@10/50及其他截断指标。配对用户bootstrap只作描述区间，无正式显著性和非劣结论。记录softmax(20×商品分数)的熵，辅助说明信号集中程度，不把它当准确率或校准可靠性。

## 核验与决定规则

读入信号来源、历史、权重和候选后先冻结两个域全部输入，再算新变体效果。独立脚本重建全部变体分数、Top50、目标名次、汇总和配对差值，核对输入哈希。

如果某变体在两域的“全目录”和“原GRAM50”上N10及H10均不退，至少一处N10相对提高0.5%，标为值得考虑下一次解码。该门槛严格限制扩大GPU投入，不表示微小下降一定有害，也不证明生成时有效。如果没有清晰信号，就保留记录，不启动同配方大规模解码。

不增加候选大小、引入新骨干、恢复失败蒸馏或穷举专家组合。本轮即使正向也不能作为独立创新点；后续仍需新监督流程和真正解码验证。

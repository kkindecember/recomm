## 序列和 leave-one-out 划分

- 序列长度最小 5、最大 204，满足 5-core 数据特征。
- `MultiTaskDatasetGRAM.load_train()` 使用每条序列的 `items[:-2]` 构造训练样本。
- validation 使用 `items[-2]` 作为唯一目标，历史为 `items[:-2]`。
- test 使用 `items[-1]` 作为唯一目标，历史为 `items[:-1]`。
- 所有 22,363 个用户均至少有 5 个交互，因此每个用户都可产生且只产生一个 validation 目标和一个 test 目标。

## full-ranking 证据

测试数据集将全部 12,101 个层次语义 ID 放入 `all_items`。runner 将这些候选编码为 Trie，并在 `generate()` 中通过 `prefix_allowed_tokens_fn` 约束 beam search；没有构造负采样候选集。默认 `beam_size=50`，生成数同时至少为 50。指标代码在 leave-one-out 的单目标设定下计算 Hit/Recall 与 NDCG。

## 审计方法

逐行按“首个空格分隔 ID 与值”的官方格式解析四个文件；统计首列唯一性、序列交互、集合差、空值、层次 ID 值唯一性、相似商品引用及每用户序列长度。另以代码静态检查确认训练/验证/测试切分和 full-ranking 候选构造。
